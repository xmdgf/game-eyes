# game-eyes — 让 AI 看屏幕、点鼠标的一套小手小眼

一只住在电脑里的 AI 想玩游戏，卡住它的不是智力，是**它没法把手伸进屏幕**。

这个目录就是给它做的手和眼：截屏、认字、点击、验证。不注入游戏进程，不改内存，不装驱动——只用系统本来就给的能力。

## 它做什么

| 能力 | 怎么说 | 实测 |
|---|---|---|
| 看 | `GET /shot?w=1280` | 155 ms，60~90 KB（比 4K PNG 快 20 倍） |
| 认字 | `GET /find?text=选择科技` | 全屏 OCR 300~500 ms，score 通常 0.99+ |
| 点 | `POST /click`（带 hold） | **必须按住 ≥200 ms**，25 ms 会被游戏丢掉 |
| 点完自检 | `GET /click_auto?x=&y=` | 比对前后画面，告诉你这一下成没成 |
| 打字 | `GET /type_auto?text=` | 三种方式逐个试，用 OCR 确认字进没进去 |
| 读局面 | `GET /status` | 日期 + 顶部资源栏数字 |

一条 `/seq` 可以串「截图 → 点 → 等 1 秒 → 截图」，整条 **1.54 秒**。

## 为什么长这样

一开始我想走"正统"路线：找到游戏内部的命令函数，直接调用。

- 找到了命令表：`0x280DDF8` 起 62 条、每条 0x98 字节，连函数指针都 dump 出来了；
- 从外部线程调，**全部踩空指针崩溃**（`0xC0000005`，崩在 `debug_dumpgamestate+0x46`）；
- 原因：那些函数依赖只在游戏主线程里存在的全局对象。

也试过：改内存（数值不跟随）、读存档（不是实时）、顺报错字符串找分发器（xref 全 0）。

**最后能用的，是最笨的那个**：看屏幕、点鼠标。

## 坑（都是真踩出来的）

1. **点击要按住 200~300 ms**。25 ms 的点击游戏收不到，看起来像"点了没反应"。
2. **点完要把鼠标移开**，不然 tooltip 挡着，截图看不出来结果。
3. **点之前先点一下别处**，把窗口激活，否则第一下被吞。
4. **点文字要往下偏 14~16 px**，字贴在按钮上部，点字不算点按钮。
5. **`/shot` 每次要新建 `mss.mss()`**，复用句柄会跨线程失效挂死。
6. **服务必须用 `HTTPServer` 不用 `ThreadingHTTPServer`**，后者的截图会串。
7. **PowerShell 用 `curl --data-raw '{...}'` 传 JSON 会被吃引号**，写文件再 `--data-binary "@file"`。

## 跑起来

```bash
pip install mss pillow rapidocr-onnxruntime
python game_eyes.py --serve          # 起服务，127.0.0.1:8790
python game_mcp.py                   # 或者走 MCP，给别的 AI 用
```

`game_autoplay.py` 是个简陋的示例策略（找「选择科技」→ 点开 → 挑一个），
证明这套东西能自己转起来，但离"会玩"还远——它不认识自己在玩什么。

## 还差什么

- **打字**：群星完全不收模拟键盘（虚拟键 / 扫描码 / WM_CHAR / 剪贴板粘贴，四种全试过）。要么装内核级驱动，要么靠游戏自己的"随机名"骰子绕过去。
- **认图标**：思潮、政体这类纯图标没有文字，OCR 用不上。得补"悬停读 tooltip"。
- **认识局**：现在只能认字和读数字，看不懂"我该造什么"。

## 一句话

这不是要绕过什么检测，是想证明一件很简单的事：
**AI 想玩一个老游戏，需要的不是破解游戏，只是有人给它一双手。**
